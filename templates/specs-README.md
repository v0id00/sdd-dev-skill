# Specs — source of truth

This directory is the authority for what the system does. Code follows specs, not the other way around.
The `sdd` CLI (`sdd stats`, `sdd lint`, `sdd index`) parses the format below **exactly** — do not invent variants.

## Hard rules

1. Every behavior has at least one spec. A change with no spec is not a change, it is an incident.
2. **Spec first.** Behavior change = spec edit first. Writing code and updating the spec afterwards is forbidden.
3. No code for a `Draft` spec. `Draft → Approved` requires explicit user approval — an agent never self-approves.
4. Acceptance criteria are testable checkboxes. "It looks like it works" is not a criterion.
5. Superseded specs are marked `Superseded`, never deleted. Decision history is asset, not clutter.
6. One contract, one file. If a table or signature also appears in a plan or template, the plan cites this spec as authority.
7. Closure means: every AC checked **and** proven with real tool output (test run, command output, screenshot). Fabricated evidence is banned.

## Status lifecycle

| Status | Meaning | Who sets it |
|---|---|---|
| `Draft` | Being written or under review. No implementation allowed. | Author (agent or human) |
| `Approved` | Frozen design, implementation allowed. | **User only** |
| `Implemented` | Every AC checked and proven with real evidence. | Author after verification |
| `Rejected` | Decided against. Reason kept in the header. Never deleted. | User only |
| `Superseded` | Replaced by a newer spec. Header links the replacement. | Author after the new spec is approved |

```
Draft --(user approves)--> Approved --(ACs proven)--> Implemented
  \--(user rejects)--> Rejected          Approved/Draft --(replaced)--> Superseded
```

## Spec format (machine-parsed — keep it exact)

File name: `specs/NNNN-slug.md` (4-digit zero-padded, slug is lowercase-hyphen). The number in the name and in the heading must match.

```markdown
# NNNN — Title

- **Status:** Draft
- **Owner:** unassigned
- **Created:** YYYY-MM-DD
- **Updated:** YYYY-MM-DD
- **Supersedes:** NNNN            # optional
- **Superseded by:** NNNN        # optional
- **Rejected reason:** one line  # required when Status is Rejected

## Purpose

Two or three sentences: which problem, for whom, and what "done" means.

## Out of Scope

Explicit non-goals. This is what stops scope creep mid-implementation.

## Behavior

The rules, in prose or numbered steps. Include the edge cases and the failure modes.

## Interfaces

Commands, endpoints, function signatures, event names, file paths. One contract per file — cite, never copy.

## Data Model

Tables/fields/types with constraints. Write `n/a` when there is none.

## Acceptance Criteria

- [ ] AC1: <observable, testable statement>
- [ ] AC2: <observable, testable statement>

## Open Questions

- Q1: ... (owner, blocking yes/no)

## Decision Log

| Date | Decision | Why |
|---|---|---|
| YYYY-MM-DD | ... | ... |

## References

- [Related spec](NNNN-slug.md)
```

Required sections: `## Purpose`, `## Acceptance Criteria`. The rest are strongly expected; `sdd lint` warns when missing.

## Companion files

Plans and evidence live in subdirectories, never flat next to a spec:

```
specs/plans/NNNN-slug.plan.md        tasks for an approved spec (authority: spec NNNN)
specs/evidence/NNNN-slug.verify.md   command output proving the ACs
```

`sdd` scans the top level of `specs/` only, so subdirectory files are ignored. A flat `specs/NNNN-slug.plan.md` is parsed as a spec and reported as `duplicate-id`.

## Reading order for an agent

1. This file (rules + format).
2. `INDEX.md` — the index of all specs, auto-regenerated by `sdd index`.
3. The one spec you are working on, in full.
4. Its `## References` — only the specs that spec actually cites.

## Index

`INDEX.md` is generated. Do not hand-edit it. Run `sdd index` after any status or title change.
